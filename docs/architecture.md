# Architecture decision — first version

## Platform assessment (2026-10-09)
This WSL2 environment provides Python 3.14.4, SQLite 3.46.1, Node 22.22.1 and npm 9.2.0. Rust, Cargo, pkg-config, GTK3 and WebKitGTK 4.1 are absent. npm registry and GitHub CLI connections fail; the configured CLI token is invalid (a separate connector later verified the account saprimad, but cannot create repositories). No applicable AGENTS.md was found in the project or its parent directories.

Before implementation we choose a runnable fallback: a framework-free TypeScript browser interface, Python standard-library HTTP backend, and SQLite. Python >=3.11 is supported. Bind exclusively to 127.0.0.1. No third-party runtime package downloads are required. This trades native packaging and React component tooling for portability and testability on the available machine. Tauri's Linux prerequisites: https://v2.tauri.app/start/prerequisites/ . A later desktop port can keep the versioned data model and API behavior; it is not part of the verified v1.

## Storage and semantics
SQLite migrations run at startup, foreign keys enabled. Every mutation and its audit event share a transaction. Original import batches and raw records persist. Records are citations; attached PDFs are reports. Studies are not inferred from citations or files. Reviewers are local personas, not authenticated users. Blinding filters decisions, notes, labels, audit, consensus and aggregate screening counts from the blinded API response; local file owners can still inspect SQLite.

Backups are versioned JSON with base64 PDF bytes, scoped to one project. Restore validates structure and references and creates a NEW project atomically. Stored PDF bytes live in SQLite to avoid database/file inconsistencies during backup. No third-party services receive project data by default.

## Version 0.2 continuation

The existing Python/SQLite/TypeScript stack and v1 database schema are retained. The original platform assessment above describes the initial version; no Rust/Tauri migration is planned for this continuation. Configured specific bind addresses and explicit Tailscale hosts are supported. `src/discovery.py` uses fixed HTTPS provider endpoints, backend-only environment secrets, bounded responses, caching and serial throttling. Discovery imports use server-held snapshots instead of trusting browser-supplied metadata. Optional fields in record JSON keep old records and backup format compatible. PDF bytes continue to live in SQLite.

GitHub Pages receives only the separate `site/` landing page. A private systemd service is prepared for an existing backend-capable Linux host. Authentication and user/project isolation are absent; public writable deployment is prohibited until implemented and verified.
